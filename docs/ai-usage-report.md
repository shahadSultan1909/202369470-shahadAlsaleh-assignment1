## 2. Benefits & Challenges

### Benefits
- Helped **organize and structure the code professionally** — I was able
  to write HTML/CSS/JS myself, but the file structure, naming
  conventions, and code organization ended up much cleaner than my
  usual approach.
- Made it easier to apply **responsive design patterns** (CSS Grid,
  Flexbox, media queries) consistently across sections.

### Challenges
- **Communicating design intent clearly**: When I first started, my
  initial design request wasn't specific enough, and the result didn't
  match what I had in mind. I learned that I needed to clearly identify
  exactly what I wanted (style, layout, colors) instead of giving vague
  instructions. This made a big difference in the quality of the output.
- **Diagnosing design issues myself**: At one point, I noticed the design
  looked weak and unpolished, and I had to figure out on my own that the
  issue was coming from the CSS. Once I identified that, I asked Claude
  to explain specific CSS concepts and reference examples so I could
  understand why the design looked the way it did, and how to fix it.
- **Understanding complex CSS code**: Some of the CSS Claude generated
  was fairly advanced (e.g., gradients, grid layouts, custom properties),
  so I regularly asked Claude to explain the code line by line to make
  sure I actually understood what each part was doing before using it.
- Needed to double check technical terms I wasn't familiar with at
  first, such as "hero section," "hamburger menu," "vanilla JavaScript,"
  and CSS "breakpoints", to make sure I actually understood the whole code.

## 3. Learning Outcomes

Working with AI on this assignment helped me:
- Learn the importance of **communicating requirements precisely** when
  working with AI tools. Vague requests led to results that didn't
  match my vision, while specific, detailed requests (with references
  or examples) produced much better results.
- Learn new **CSS concepts** I hadn't used before, such as design tokens
  (CSS custom properties/variables for consistent theming), CSS reset
  rules, and responsive breakpoints (`@media` queries for tablet/mobile).
- Learn common **web development terminology** I wasn't familiar with,
  including "hero section," "hamburger menu," "vanilla JavaScript"
  (plain JS without frameworks/libraries), and "thumbnail" (a small
  representative icon).
- Practice **reading and understanding generated code critically** line
  by line before using it, rather than copying it without comprehension.
- Understand how to write a **clean, professional file structure** for a
  web project (separating HTML, CSS, and JS, and documenting each part).
